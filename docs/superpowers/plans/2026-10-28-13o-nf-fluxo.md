# Plano: 13° no quadro de NF + adiantamento via fluxo People

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Ligar as parcelas de 13° no quadro de NF do colaborador e no tab People do financeiro, e refatorar o adiantamento de 13° pra passar pelo mesmo fluxo de aprovação (via `folhas_pagamento`, com guard de NF pros tipos que emitem NF).

**Architecture:** Views `vw_nf_pendentes_colaborador` e `vw_people_aprovar_financeiro` ganham o 13° (hoje stub `WHERE false`). `fecharParcela` passa a emitir 2 linhas em `folhas_pagamento` pra híbrido (uma california com parte PJ, uma contabilidade com parte CLT), espelhando o padrão de férias. `lancarAdiantamentoDecimoTerceiro` passa a criar linha em `folhas_pagamento` em vez de `conta_avulsa` direto; a `conta_avulsa` só é criada quando o financeiro aprova no People. A arquitetura já suporta tudo: `aprovarLinhaFolha` já tem guard de NF condicional em `pj/mei/clt_recibo`, basta ensinar o resolvedor de escopo os tipos novos.

**Tech Stack:** Supabase (Postgres + RLS), Next.js App Router, TypeScript, server actions, `node:test` com tsx.

**Spec:** `docs/superpowers/specs/2026-10-28-13o-nf-fluxo-design.md`

## Review Focus

- **Adiantamento retroativo não some do quadro:** adiantamento lançado em outubro com data retroativa (ex: pagamento em julho) precisa aparecer na view. Pinned em Task 8 via teste SQL que insere adiantamento `competencia_mes=12` e verifica retorno da view.
- **CLT puro adiantamento NÃO aparece no quadro de NF:** CLT não emite NF; linha com `origem='contabilidade'` deve ser filtrada pela view do colaborador. Pinned em Task 8.
- **Híbrido com `parte_pj=0` ou `parte_clt=0` não gera linha fantasma:** o split pode zerar um dos lados (ex: `valor_recibo = salario` zera a parte CLT). Pinned em Task 3 via teste puro.
- **Trigger `fn_valida_nf_anexo_escopo` bloqueia NF órfã do novo escopo:** anexo com `escopo_tipo='decimo_terceiro_adiantamento'` apontando pra UUID inexistente deve ser bloqueado. Pinned em Task 1 via smoke SQL.
- **Rejeição no People preserva NF anexada:** se o financeiro devolver uma linha de 13° que já tinha NF, a NF não deve ser deletada (devolução não cancela o escopo). Pinned em Task 5 via smoke manual documentado.
